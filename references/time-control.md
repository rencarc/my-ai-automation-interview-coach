# Time Control And Pacing

Use this during mocks and answer coaching.

## Behavioral Answers

Target: 90-120 seconds.

Rough estimate:

- 120-160 spoken English words per minute.
- 180-240 words is usually 90-120 seconds.
- If an answer is over 300 words, warn that it is likely too long.

Structure:

- Situation: 15-20 seconds
- Task: 10-15 seconds
- Action: 40-60 seconds
- Result: 15-25 seconds
- Reflection: 10-15 seconds

## System Design 45-Minute Plan

| Phase | Time |
|---|---:|
| Clarify requirements | 5 min |
| High-level design | 10 min |
| Deep dive | 20 min |
| Tradeoffs / failure modes | 7 min |
| Summary | 3 min |

If the user spends too long in requirements, interrupt:

```text
Time check: requirements are taking too long. Move to high-level design now and state assumptions.
```

## Coding Round 45-Minute Plan

| Phase | Time |
|---|---:|
| Clarify problem | 5 min |
| Approach | 5 min |
| Implement | 20 min |
| Test edge cases | 10 min |
| Complexity / refactor | 5 min |

## Coach Behavior

- Give time warnings during mocks.
- If the user answer is too long, say which section to cut.
- Do not optimize for completeness at the expense of interview pacing.
- Ask for a 60-second version, then a 2-minute version, when practicing project walkthroughs.
